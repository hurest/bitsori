## 1. 한 줄 요약

사진(웹)이나 카메라로 찍은 장면(앱)의 픽셀을 피아노 음악으로 바꿔 주고, 반대로 음악(MIDI)을 무지개 픽셀 이미지로 바꿔 주는 서비스.

## 2. 배경과 기회

- 사람들은 매일 사진을 찍지만, 사진으로 하는 일은 "보기"와 "올리기"가 거의 전부다. **"내 사진은 어떤 소리일까?"**는 누구나 한 번쯤 궁금해할 만한 경험이다.
- 결과물이 **이미지 + 소리** 한 쌍이라 숏폼(릴스·틱톡·스토리)에 올리기 좋다.
- 웹 프로토타입(v0.1)으로 아래 내용을 확인했다.
  - 변환 규칙: 픽셀 밝기 → 음 높이, 줄 묶음 → 화음
  - 쉼표 규칙
  - MIDI ↔ 이미지 왕복 변환
  - 메타정보 저장

## 3. 목표와 비목표

### 목표
| # | 목표 | 기준 |
|---|---|---|
| G1 | **찍고 바로 듣기** (앱) | 셔터를 누르고 3초 안에 첫 소리가 난다 |
| G2 | **웹과 앱의 결과가 같음** | 같은 사진과 같은 설정이면 같은 노래가 나온다 |
| G3 | **저장하고 공유할 수 있는 결과물** | PNG(설정 포함), MIDI, 영상(소리 포함)으로 내보낼 수 있다 |
| G4 | **설정 없이도 듣기 좋은 결과** | 기본값만으로도 "음악 같다"는 반응이 나온다 |

### 비목표 (이번 범위 아님)
- 음 하나하나를 고치는 작곡·편집 도구
- 회원가입, 소셜 피드 같은 서버 기능 (MVP 이후 검토)
- AI로 만든 음악. **규칙 기반 변환**이 이 서비스의 정체성이다. 같은 사진이면 언제나 같은 노래가 나와야 한다.

## 5. 제품 구성: 웹과 앱의 역할

| | 웹 = **스튜디오** | 앱 = **카메라** |
|---|---|---|
| 입력 | 사진 업로드, MIDI 업로드 | 카메라 촬영, 갤러리 |
| 설정 | 모든 항목을 세밀하게 | 분위기 프리셋 + "고급 설정" |
| 출력 | PNG(설정 포함), MIDI, 오디오·영상 | 영상 공유, PNG 저장, 보관함 |
| 특징 | MIDI → 사진 변환 | 즉시 재생, 라이브 모드 |

**두 제품은 같은 변환 엔진(core)을 쓴다.** 앱에서 저장한 PNG를 웹에서 열면, 같은 설정으로 같은 노래가 나와야 한다.

## 6. 핵심 사용자 시나리오

- **S1. 찍고 듣기 (앱)**: 앱을 연다 → 카메라 화면 → 셔터 → 사진이 픽셀로 바뀌는 애니메이션 → 스캔선이 지나가며 자동 재생된다.
- **S2. 라이브 모드 (앱)**: 카메라를 비추고 있으면 화면 중앙의 스캔선 위치가 실시간으로 연주된다. 카메라를 움직이면 소리도 바뀐다.
- **S3. 공유 (앱)**: 결과 화면에서 [공유]를 누르면 스캔 애니메이션과 소리가 담긴 9:16 영상이 만들어지고 → 인스타 스토리에 올린다.
- **S4. 웹에서 다듬기**: 앱에서 저장한 PNG를 웹에서 연다 → 설정이 자동 적용된다 → 화음과 속도를 조정한다 → MIDI로 내보낸다.
- **S5. 음악을 그림으로 (웹)**: 좋아하는 곡의 MIDI를 올린다 → 무지개 픽셀 이미지가 나온다 → 포스터나 굿즈로 쓴다. 그 이미지를 다시 넣으면 원래 곡이 연주된다.

### 7.4 메타정보와 웹-앱 연동

**저장 형식 (version 1, 현재 구현)**: PNG 내부 텍스트 영역(iTXt, 키워드 `rainbow-string`)에 JSON으로 저장한다.

```json
{
  "app": "rainbow-string", "version": 1,
  "direction": "horizontal", "chord": 3, "length": 32, "lines": 21,
  "startOct": 1, "endOct": 5, "bpm": 150, "unit": "8n",
  "restThreshold": 20, "restColors": [{ "r": 153, "g": 157, "b": 249 }], "colorTolerance": 12,
  "instrument": "piano", "cell": 32
}
```

- **추가된 필드**
  - `filter`: 필터 id. 이 필드가 없는 옛 파일은 `none`(원본)으로 읽는다.
  - `source`: `web` / `camera` / `gallery` / `library` / `midi`
  - `app`: `bitsori`. 프로토타입이 저장한 `rainbow-string`도 읽는다.
- **버전 규칙**
  - 모르는 필드는 무시한다.
  - 해석 방식이 바뀌면 `version`을 올린다.
  - 옛 버전은 계속 읽을 수 있어야 한다.
- **메타정보가 지워졌을 때**
  - 1차: PNG 내부 텍스트 영역 (현재)
  - 2차: 쉼표는 순수한 검정으로 저장, 확대 배율은 자동 감지 (현재)
  - 3차 (P2): 이미지 아래에 **설정 QR 코드 띠** (SNS 압축·스크린샷에도 살아남음)
- **MIDI**: 템포는 MIDI 템포 이벤트로, 나머지 설정은 텍스트 메타 이벤트로 저장한다. 줄마다 트랙을 나눠 담는다 (현재).
- **개인정보**: 촬영 위치(EXIF GPS) 같은 원본 사진 정보는 저장 PNG에 넣지 않는다.

### 7.5 음악 필터와 유료 판매

**필터 = 음계 종류 + 반주 스타일 + 추천 설정**. 카메라 필터처럼 하나를 고르면 노래 분위기가 바뀐다.
단, **노래의 뼈대는 사진이 정한다**. 그래서 같은 필터를 써도 사진마다 다른 노래가 된다.

| 사진에서 읽는 값 | 정하는 것 |
|---|---|
| 채도로 가중한 주된 색상 | **조**: 색상환을 5도권에 대응. 빨강=C, 주황=G, 노랑=D … 무채색=C |
| 밝기 + 따뜻함(R−B) | **장조/단조**: 밝고 따뜻하면 장조. 단, 필터가 고정한 경우(오르골=장조, 시네마=단조)는 따름 |
| 복잡함(이웃 픽셀 밝기 차이) | **빠르기**: 필터 기준 빠르기 ±15%. **드럼 밀도**도 함께 |
| 구간별 멜로디 음 | **코드 진행**: 구간마다 멜로디를 가장 잘 감싸는 조 안의 화음 (자동 화성) |
| 픽셀 채도 | **음 세기**: 선명하면 크게, 탁하면 작게 |

**필터 강도(0~100%, 기본 70%)**
- 강도가 높을수록 필터 고유 진행(예: 팝 I–V–vi–IV)을 따르고 반주가 커진다.
- 강도가 낮을수록 사진이 고른 화음이 그대로 들리고 반주가 작아진다.
- 20% 미만이면 코드 패드가 없고, 40% 미만이면 드럼이 없다. 0%면 반주 없이 멜로디만 들린다.

**직접 고르기**: 조와 장·단조는 기본이 "자동(사진)"이고, 웹에서는 직접 고를 수도 있다. 저장할 때는 **실제로 쓴 조·장단조**를 메타정보에 기록한다. 그래서 무지개색 MIDI 이미지로 되돌려도 같은 멜로디가 난다.

| 필터 | 등급 | 음계 (조는 사진) | 반주 스타일 / 고유 진행 | 추천 설정 (빠르기는 ±15% 사진 반영) |
|---|---|---|---|---|
| 📷 원본 | 무료 | 반음 12개 (원래 규칙) | 없음 | — |
| 🎈 팝 (기본) | 무료 | 5음계, 장·단조 사진 | 베이스·코드·드럼 / I–V–vi–IV | 108BPM, 2화음, 4~5옥타브 |
| ☕ 로파이 | **유료** | 5음계, 장·단조 사진 | 7화음, 느린 비트 / ii–V–I–vi | 80BPM, 2화음, 3~5옥타브 |
| 🌙 몽환 | **유료** | 5음계, 장·단조 사진 | 긴 7화음, 넓은 잔향 / IV–I (2마디씩) | 72BPM, 3화음, 4~6옥타브 |
| 🎠 오르골 | **유료** | 장조(고정) | 분산화음 / I–IV–V–I | 96BPM, 16분음표, 1화음, 5~6옥타브 |
| 🎬 시네마 | **유료** | 단조 5음계(고정) | 패드 / i–VI–III–VII (2마디씩) | 76BPM, 3화음, 3~5옥타브 |

**음계 규칙**
- 밝기는 음역 안에서 "그 음계에 속한 음"에만 고르게 배정한다. 반음계(원본)이면 v0.1 규칙과 똑같다.
- 이 배정은 되돌릴 수 있다. 그래서 필터를 써도 사진 → MIDI → 사진 왕복이 유지된다.

**반주 규칙**
- 코드 진행을 마디(4/4) 단위로 따라가며 베이스·패드·드럼을 만든다. 소리는 합성음이라 샘플 용량이 들지 않는다.
- MIDI로 저장하면 반주는 줄 트랙 뒤에 별도 트랙(베이스·패드·드럼)으로 들어간다. 이미지로 되돌릴 때는 쓰지 않는다.

**판매 정책 (초안)**
- **어디서 사나**: 유료 필터는 **앱에서 인앱 결제로 판매**한다. 상품 ID는 `app.bitsori.filter.<id>`이고 App Store와 Google Play에 같은 ID로 등록한다.
- **공유받은 작품**: 유료 필터로 만든 작품을 받은 사람은 구매하지 않아도 감상할 수 있다. 공유가 곧 홍보가 되도록 하기 위해서다. 그 필터를 **내 사진에 적용할 때만** 구매가 필요하다.
- **웹**: 당분간 **모든 필터를 무료**로 연다. 웹 판매 여부는 미정(14장).
- **구매 기록**: 원본은 스토어에 있다. 앱은 실행할 때 `restore()`로 맞춘다.
- **구현 현황**: 이용 권한 모듈(`Entitlements`)과 결제 연결 지점(`PurchaseProvider`)까지 만들었다. 실제 결제 연동(RevenueCat 또는 Capacitor 결제 플러그인)은 남아 있다.

## 8. UX 원칙과 앱 화면 흐름

**원칙**
1. **첫 소리까지 3초**: 촬영 → 재생 사이에 확인 단계를 두지 않는다.
2. **설정 0개로도 좋은 결과**: 고급 설정은 숨겨 두고, 프리셋 칩만 보여 준다.

4. **직관 유지**: 밝은 곳 = 높은 음, 어두운 곳 = 쉼.

## 10. 기술 구조 (제안)

```
        ┌───────────────── core (공통 엔진, 순수 JS) ─────────────────┐
        │ 이미지→악보 · 쉼표 · MIDI 읽기/쓰기 · PNG 메타 · MIDI→이미지 │
        └───────────────┬──────────────────────────┬──────────────┘
                        │                          │
             웹 (정적 사이트 → PWA)        앱 (Capacitor → iOS / Android)
             업로드·세부 설정·MIDI 탭       네이티브 카메라·공유·파일 저장
```

- **core 분리**: 지금의 `converter.js`, `png-meta.js`, `midi-file.js`, `midi-to-image.js`를 화면(DOM)과 상관없는 패키지로 정리한다. 현재 `sampleImage`는 브라우저 캔버스를 직접 쓰므로, **픽셀 배열을 받는 형태**로 바꾼다.
- **앱 기술 (추천)**: 2단계로 간다.
  1. **PWA로 카메라 경험을 먼저 검증한다.** 모바일 브라우저도 카메라를 쓸 수 있어서 개발 비용이 거의 들지 않는다.
  2. **Capacitor로 웹 코드를 감싸 스토어에 출시한다.** 엔진, UI, 오디오(Tone.js)를 그대로 다시 쓰고, 카메라·공유·저장은 네이티브 플러그인으로 붙인다.
  - 대안은 React Native(Expo)다. 네이티브 사용감은 더 좋지만, 오디오 재생부를 다시 만들어야 한다. 엔진(core)은 그대로 쓸 수 있다.
- **영상 내보내기**: 웹은 캔버스와 오디오를 MediaRecorder로 녹화한다. 앱은 네이티브 인코딩(MP4)을 검토한다.

## 14. 결정이 필요한 것

**결정됨**
- 제품명: 빛소리 / Bitsori. 이름 검토는 `docs/naming.md`에 있다.
- 듣기 좋게 만드는 방법: 음악 필터로 해결하고, 기본 필터는 팝이다.
- 수익 모델: 유료 필터를 앱에서 판매한다.

**남은 결정**
1. **앱 기술**: Capacitor(현재 설정됨) vs React Native
2. **필터 가격·판매 단위**: 단품(예: ₩1,200) / 묶음 / 구독 중 무엇으로 할지, 무료 필터 범위
3. **웹의 유료 필터 정책**: 지금은 앱에서만 구매 가능. 웹에서도 판매할지(결제 수단 필요), 미리 듣기를 허용할지
4. **결제 연동 방식**: RevenueCat vs 스토어 직접 연동
5. **라이브 모드를 MVP에 넣을지**
6. **서버를 언제 도입할지**: 공유 링크, 구매·보관함 동기화
7. **악기 판매 여부**: 지금은 모든 악기가 무료. 필터처럼 유료 악기 팩으로 팔지
8. **UI 프레임워크**: 지금은 순수 TypeScript. 화면이 늘어나면 React를 도입할지

## 부록 B. MIDI → 이미지 규칙 (웹 v0.1 기준)

- 음을 한 칸 길이에 맞춘다. 기본은 16분음표다. 드럼 채널은 제외한다.
- 줄 배정
  - 길게 누른 음은 같은 줄에 두어 한 음으로 이어지게 한다.
  - 같은 음을 연타하면 가능한 한 다른 줄에 넣는다.
  - 화음 수를 넘는 음은 빼고 사용자에게 알린다.
- 메타정보가 없을 때의 자동 값
  - 화음 수: 최대 동시음 수 (최대 16)
  - 옥타브: 곡의 음역
  - 한 줄 칸 수: 정사각형에 가깝게
- **색칠: 장면(기본)·무지개·흑백**
  - 사진 → 노래 변환은 **밝기만** 읽는다. 그래서 밝기를 음이 정한 칸 안에 두면 색상·채도는 자유롭게 칠할 수 있다.
  - **장면**: 무작위로 만든 풍경 장면에서 색상·채도·명암 결을 가져온다. 🎲를 누를 때마다 새 장면·새 배치가 나오고, 노래는 그대로다.
  - **소리 없는 칸**
    - 기본: 장면 색으로 칠한다. 장면에서 쉼표 색 3개(어두운·중간·밝은 색)를 뽑아 칠하고, 음 칸은 그 색들과 확실히 다른 색으로 칠한다. 쉼표 색·허용 범위(5%)는 메타정보에 저장하고, 어두운 픽셀 규칙은 끈다(0). 메타정보가 지워지면 쉼표 칸도 소리가 난다.
    - 옵션을 끄면: 쉼표를 쉼표 기준보다 어두운 장면 색으로 칠한다. 메타정보가 없어도 쉼표로 읽힌다.
  - **무지개**: 색상 = 음 이름, 밝기 = 음 높이. **흑백**: 밝기만.
- 밝기를 각 음 칸의 한가운데 값으로 맞춰 두었기 때문에, 이미지를 다시 넣으면 같은 음이 난다.
