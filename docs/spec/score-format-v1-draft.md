# 악보 이미지 형식 v1 — 초안

> 형식 이름은 미정이다(가칭: **Bitsori Score**). 이 문서는 아이디어와 설계를 정리한 초안이며, 아직 구현과 맞추지 않았다.
> 원조: 빛소리(Bitsori). 규격 주소(예정): `https://bitsori.app/spec/score/1` — 도메인 등록 전.

| 항목 | 내용 |
|---|---|
| 상태 | 초안 0.1 (2026-10-28) |
| 관련 문서 | [컨셉과 방향](../concept.md) · [PRD](../PRD.md) |

## 1. 목표

**빛소리가 없어도, 이 문서만 보고 누구나 같은 노래를 재현할 수 있는 규칙.**

- 이미지 → 노래, 노래(MIDI) → 이미지를 **결정적으로** 정의한다. 같은 입력이면 언제나 같은 결과다.
- 어떤 프로그래밍 언어로 구현해도 결과가 같다 (정수 연산으로 정의).
- 메타정보가 손실돼도 최대한 살아남는다 (여러 그릇 + 보이는 그릇).
- 다른 서비스가 자기 해석 방식을 더할 수 있다 (프로필).
- 빛소리는 원조로 남는다 (11장).

## 2. 용어

| 용어 | 뜻 |
|---|---|
| **악보 이미지** | 이 형식의 규칙대로 노래를 담은 이미지 |
| **격자** | 노래를 담는 칸들의 배열 (cols × rows). 한 칸 = 이미지에서 `cell × cell` 픽셀 |
| **줄** | 시간 방향으로 읽는 칸의 열. 가로 방향이면 행, 세로 방향이면 열 |
| **성부(voice)** | 화음 안의 한 줄. 줄을 `voices`개씩 묶은 것이 **묶음** |
| **칸 번호(step)** | 연주 순서. `묶음 번호 × 줄 길이 + 줄 안의 위치` |
| **값** | 칸에서 읽은 밝기 (0~255) |
| **음 목록** | 값을 배정할 MIDI 음들 (음계에 속한 음만) |
| **무지개 줄** | 격자 아래에 붙는 메타정보 띠 (보이는 그릇) |
| **프로필** | 칸 → 음 해석 방식. 기본은 `bitsori:luma` |

## 3. 세 겹 구조

```
① decode  (필수)  — 이것만 있으면 누구나 같은 음을 얻는다. 모르는 항목이 있으면 해석을 거부해야 한다.
② render  (선택)  — 어떻게 들려줄지. 무시해도 음은 같다.
③ origin  (선택)  — 누가·언제·어떻게 만들었나 + 검증값
```

- **"자동"은 파일에 쓰지 않는다.** 사진 색으로 조를 정하는 것 같은 자동 기능은 앱 화면의 기능이다. 파일에는 **실제로 쓴 값**만 기록한다.
- **유료 필터의 음계 효과**는 ①에 숫자(음계·으뜸음)로 풀어 쓴다. 그래서 누구나 멜로디를 재현할 수 있다. **반주 스타일**은 ②에 이름(`bitsori:lofi`)으로만 남긴다. → "노래는 개방, 소리는 빛소리"

## 4. 해석 규칙 (프로필 `bitsori:luma`)

입력은 회전 정보(EXIF Orientation)를 적용하고 sRGB 8비트 RGBA로 변환한 이미지와 메타정보 `M`이다.

```
1. 무지개 줄이 있으면 떼어 낸다 (6장).
2. 격자 읽기: 칸 (c, r)의 색 = 이미지 픽셀 (c·cell + ⌊cell/2⌋, r·cell + ⌊cell/2⌋)   — 칸 가운데 한 점
3. 값 Y = ⌊(299·R + 587·G + 114·B + 500) / 1000⌋                                   — 0~255, 정수 연산
4. 쉼표 여부 (하나라도 해당하면 쉼표):
     A < 128                                            — 투명
     Y < T                                               — 어두움 (T = rest.below)
     어떤 쉼표 색 (cr,cg,cb)에 대해 (R−cr)² + (G−cg)² + (B−cb)² ≤ D²   — D = rest.distance (정수)
5. 음 목록 P = [ m | low ≤ m ≤ high,  (m − tonic) mod 12 ∈ scale ]   (낮은 음부터),  n = |P|
6. 음 번호 k = ⌊(Y − T) · n / (256 − T)⌋   (정수 나눗셈),  음 = P[k]
7. 읽는 순서: direction = rows면 줄 = 행(위→아래), 줄 안 = 왼쪽→오른쪽
              direction = cols면 줄 = 열(왼쪽→오른쪽), 줄 안 = 위→아래
   줄 L개(길이 len)를 voices개씩 묶는다. 묶음 g의 성부 v = 줄 (g·voices + v)
   칸 번호 s = g·len + 위치
8. 이음: 같은 성부에서 같은 음이 바로 이어지면 한 음으로 합친다 (길이 = 이어진 칸 수)
9. 시간: 한 칸 = step(예: 1/8 음표). 칸 s의 시작 = s × step, BPM = time.bpm
```

- **결과**: 음표 목록 `(시작 칸, 길이, 성부, MIDI 음)`.
- **MIDI → 이미지**는 위의 역과정이다. 음 번호 k의 값은 그 칸의 **한가운데**(`T + (k + ½)(256 − T)/n`)로 칠한다.
- **일반 사진**(메타정보 없는 사진)을 줄이는 방법은 v1에서 정의하지 않는다. 결과가 구현마다 다를 수 있다. "같은 사진이면 어디서든 같은 노래"는 v2의 선택 프로필(정규 축소)로 검토한다.

## 5. 데이터 구조 (JSON)

```json
{
  "format": "https://bitsori.app/spec/score/1",
  "profile": "bitsori:luma",
  "grid": { "cols": 32, "rows": 21, "cell": 32, "string": "bottom" },
  "decode": {
    "rest": { "below": 20, "colors": [[153, 157, 249]], "distance": 22 },
    "pitch": { "low": 60, "high": 83, "tonic": 7, "scale": [0, 2, 4, 7, 9] },
    "read": { "direction": "rows", "voices": 2, "tie": "merge" },
    "time": { "step": "1/8", "bpm": 108, "meter": "4/4" }
  },
  "render": {
    "instrument": { "gm": 0, "id": "bitsori:piano" },
    "style": { "id": "bitsori:pop", "strength": 70 },
    "expression": { "velocity": "saturation" }
  },
  "origin": {
    "generator": "Bitsori Web 0.6",
    "created": "2026-10-28T09:00:00Z",
    "source": "camera",
    "art": "sunset#4821"
  },
  "check": { "notes": "crc16:9f3a", "grid": "sha256:…" }
}
```

- **`origin.source`**: 만들어진 곳. `camera` · `gallery` · `web` · `midi` · `photo+midi` (사진 + MIDI 콜라보)
- **음 높이는 MIDI 번호(0~127)로 적는다.** "가운데 도"가 C4인지 C3인지는 프로그램마다 달라서, 옥타브 번호를 쓰면 혼란이 생긴다.
- **`check.notes`**: 해석 결과 음표 목록의 CRC-16. 노래를 올바로 복원했는지 확인할 때 쓴다 (7장).
- **`check.grid`**: 격자 픽셀의 해시. 다른 프로그램이 그림을 편집해서 메타정보와 픽셀이 어긋났는지 확인할 때 쓴다.
- **ID 이름**: `회사도메인:이름` 형태로 겹치지 않게 한다 (예: `bitsori:pop`, `com.example:hue-pitch`).

## 6. 그릇: 하나의 내용, 여러 저장 방식

| 그릇 | 대상 | 방식 |
|---|---|---|
| **XMP** | PNG·JPEG·WebP·HEIC | 네임스페이스 `https://bitsori.app/ns/score/1/`, 속성 하나에 위 JSON을 담는다. 사진 업계 표준이라 편집 프로그램이 보존하는 경우가 많다 |
| **PNG iTXt** | PNG | 키워드 `bitsori`. v0(현재 구현)과의 호환용 |
| **MIDI FF 7F** | .mid | 제조사 전용 메타 이벤트. 작곡 프로그램 화면에 보이지 않는다. 내용: `"BTSR"` + 버전 + JSON. ※ 상용 표준이 되려면 MIDI 협회의 제조사 ID 확보를 검토한다 |
| **JSON 파일** | 웹 API·교육 도구 | 파일 형식 이름 `application/vnd.bitsori.score+json` (IANA 등록 검토) |
| **무지개 줄** | 모든 이미지 | 보이는 그릇. 아래 6.1 |

### 6.1 무지개 줄 (보이는 그릇)

```
│▮▯▮▯│🟥🟨🟩🟦│ 데이터 116모듈 │▯▮▯▮│      ← 이미지 맨 아래, 격자 바깥
 시작    색 기준                  끝
```

| 항목 | 초안 값 | 이유 |
|---|---|---|
| 위치 | 격자 바로 아래, 이미지 전체 폭 | 노래에 포함되지 않음 |
| 높이 | 이미지 폭의 1/48 (최소 8px) | SNS에서 축소돼도 남는 두께 |
| 모듈 수 | 가로 128등분 (해상도와 상관없이 고정) | 1080px로 줄어도 모듈 하나가 약 8px |
| 시작·끝 표시 | 검·흰·검·흰 / 흰·검·흰·검 (각 4모듈) | 일반 사진을 잘못 읽지 않게 하고, 뒤집힘도 알아냄 |
| 색 기준 | 빨강·노랑·초록·파랑 (4모듈) | 데이터에 쓰는 4색의 실제 모습. 압축으로 틀어진 색을 보정한다 |
| 데이터 | 116모듈 × 2비트 = **29바이트** | 4색 = 2비트 |
| 오류 복구 | Reed-Solomon 12바이트 | 일부 모듈이 망가져도 복구 |
| 담는 내용 | 17바이트 (아래) | |

**무지개 줄에 담는 내용 (17바이트 이내, 비트 단위)**

| 항목 | 비트 | 비고 |
|---|---|---|
| 형식 버전 | 4 | |
| 방향 | 1 | |
| 성부 수 − 1 | 4 | 1~16 |
| 격자 cols, rows | 10 + 10 | 최대 1024 |
| 최저음, 최고음 | 7 + 7 | MIDI |
| 음계 | 12 | 12음 중 쓰는 음 표시 |
| 으뜸음 | 4 | |
| 쉼표 밝기 기준 T | 8 | |
| 쉼표 색 사용 여부 | 1 | 쉼표 색 자체는 줄에 담지 않는다. 사용 중이면 내부 메타정보가 필요하다는 표시 |
| 한 칸 길이 | 2 | 1/4, 1/8, 1/16, 예약 |
| BPM − 40 | 8 | 40~295 |
| 악기(GM), 스타일 번호, 강도 | 7 + 8 + 7 | 연주 힌트 |
| 음 검증값 (CRC-16) | 16 | |
| 합계 | 136 | 17바이트 |

**QR 재생 링크 (선택)**
- 무지개 줄 오른쪽 끝에 작은 QR을 둘 수 있다.
- 담는 내용: `https://bitsori.app/p#<무지개 줄과 같은 데이터, base64url>`
- 휴대폰 기본 카메라로 찍으면 웹에서 재생된다.

## 7. 살아남기: 정보원 우선순위와 강건성

**어디서 설정을 읽나 (우선순위)**
1. 파일 내부 메타정보 (XMP → iTXt → MIDI 이벤트)
2. 무지개 줄
3. 기본 규칙 (v1 기본값: 반음계, MIDI 24~71, T = 20, 가로, 1성부, 1/8, 120 BPM. 확대 배율은 같은 색 블록으로 감지)
4. 둘 이상이 서로 다르면 `check.notes`(음 검증값)가 맞는 쪽을 따른다.

**공유용으로 저장할 때 권장하는 것**
- **밝기를 음 칸의 한가운데로 맞춘다.** 음은 같은데 JPEG로 밝기가 흔들려도 옆 음으로 넘어가지 않는다.
- 쉼표는 `T`보다 충분히 어둡게 칠한다 (예: `T − 5` 이하).
- 칸은 확대해서 저장한다 (긴 변 1024px 이상 권장).

**읽을 때 스스로 고치기 (선택 기능)**
- 경계에 걸린 칸이 몇 개면, 이웃 음 후보로 바꿔 보며 음 검증값이 맞는 조합을 찾는다.

## 8. 프로필: 다른 해석 방식 더하기

- **표준 본체**는 "격자를 시간에 따라 음으로 읽는다"는 틀만 정한다. 격자, 읽는 순서, 시간, 그릇, 무지개 줄이 여기에 속한다.
- **칸 → 음 해석**은 프로필이 정한다.
  - `bitsori:luma`: 밝기 → 음 높이. 원조이자 기본 프로필.
  - 예: `com.example:hue-pitch` (색상 → 음), LED 설치미술, 직물 패턴 → 리듬, 영상 프레임 → 마디
- **프로필 등록**: 공개 저장소에 등록 제안을 올린다. 이름에 만든 곳이 남는다.

## 9. 버전과 호환

- `format` 주소의 숫자가 큰 버전(major)이다. 해석이 바뀌면 올린다.
- 항목만 추가될 때는 큰 버전을 올리지 않는다. 읽는 쪽은 모르는 **선택 항목(render·origin)**은 무시한다.
- **`decode` 안의 모르는 항목은 무시하면 안 된다.** 노래가 달라질 수 있으니 해석을 거부하거나 경고한다. PNG 규격의 필수 청크 원리와 같다.

### 9.1 v0(현재 구현) → v1 변환

| v0 (지금 저장되는 값) | v1 |
|---|---|
| `app: "bitsori"` / `"rainbow-string"`, `version: 1` | `format` |
| `chord` | `decode.read.voices` |
| `direction: horizontal/vertical` | `rows` / `cols` |
| `length`, `lines` | `grid.cols`, `grid.rows` (방향에 따라) |
| `startOct`, `endOct` | `pitch.low = (startOct+1)×12`, `pitch.high = (endOct+2)×12 − 1` |
| `filter` + `key` + `mode` | `pitch.scale`, `pitch.tonic` (필터의 음계를 숫자로) + `render.style.id` |
| `restThreshold` | `rest.below` |
| `restColors` + `colorTolerance`(%) | `rest.colors` + `rest.distance = ⌊tolerance/100 × 441.67⌋` |
| `unit: 4n/8n/16n` | `time.step: 1/4, 1/8, 1/16` |
| `bpm`, `instrument`, `strength` | `time.bpm`, `render.instrument`, `render.style.strength` |
| `cell`, `source`, `art` | `grid.cell`, `origin.source`, `origin.art` |
| 필터 필드 없음 | 원본(반음계) |
| 필터는 있는데 조 없음 (v0.1) | 그때의 고정 조 (팝·로파이·몽환·오르골 = C 장조, 시네마 = A 단조) |

### 9.2 현재 구현과 다른 점 (v1 구현 시 맞출 것)

| 항목 | 현재 구현 | v1 규칙 |
|---|---|---|
| 밝기 계산 | 실수 계산 후 반올림 | 정수식 `⌊(299R+587G+114B+500)/1000⌋` |
| 음 번호 계산 | 실수 나눗셈 | 정수 나눗셈 |
| 쉼표 색 범위 | % | 정수 거리 |
| 음 범위 | 옥타브 번호 | MIDI 번호 |
| MIDI 저장 | 텍스트 이벤트 | FF 7F 이벤트 |
| 이미지 저장 | PNG iTXt만 | XMP + iTXt + 무지개 줄 |
| 검증값 | 없음 | 음 CRC, 격자 해시 |

## 10. 적합성 (맞게 구현했는지 확인하는 방법)

- **기준 테스트 데이터**: 기준 이미지와 정답 음표 목록 쌍을 공개한다.
  - 경계값(음 칸 경계 ±1), 투명 픽셀, 쉼표 색 경계, 세로 방향, 84음 음역, 5음계, 무지개 줄 손상, JPEG 재압축 같은 까다로운 경우를 포함한다.
- **적합성 단계**
  - L1 읽기: 이미지 → 음
  - L2 쓰기: 음 → 이미지 + 메타정보
  - L3 무지개 줄 읽기·쓰기
- **참조 구현**: 빛소리의 변환 엔진(`packages/core`)을 v1에 맞춰 공개 라이브러리로 낸다.
- **검사기**: 파일을 넣으면 규격 위반을 알려 주는 웹 도구.

| 기준 테스트 데이터 공개 | "맞게 구현했는지"의 기준을 원조가 갖는다 |
| 프로필 이름 규칙 | 기본 프로필 `bitsori:luma`가 원조로 남는다 |
| 무지개 줄 | 보이는 서명. 어떤 앱이 만든 악보 이미지든 모양이 같다 |
| 호환 인증 마크 ("Works with Bitsori" 등) | 형식은 개방하고, 로고·이름 사용은 인증으로 관리한다 |
| 상표 | 빛소리/Bitsori, 형식 이름, 인증 마크 |
| 공개 등록 기록 | IANA 파일 형식 등록, 공개 저장소의 최초 공개 커밋 |
| 운영 | 처음엔 원조가 최종 결정권을 갖고, 변경은 공개 제안서(RFC)로 받는다. 많이 쓰이면 재단 형태를 검토한다 |

## 12. 미결정 사항

1. **형식 이름**: 빛소리를 이름에 넣을지(A), 중립 이름 + 원조 표시로 갈지(B, 추천)
2. **일반 사진 결과 통일**(정규 축소 프로필)을 v1에 넣을지 (추천: v2 선택 프로필)
3. **무지개 줄 수치**: 모듈 수, 높이, 4색 값, 오류 복구 강도는 SNS 업로드 실험으로 확정한다 (인스타그램·카카오톡·X 재압축)
4. **QR 재생 링크**를 기본으로 붙일지
5. MIDI 제조사 ID 확보 여부
6. 운영 주체(개인/회사)에 따른 상표·라이선스 명의 → 법무 확인 필요
